## 四、设计说明

### 4.1 核心概念

主题定为「一纸山河」：把 24 个节气想象成同一本纸本图鉴里的 24 页，而不是 24 张互不相关的海报。

统一性主要来自四件事：

1. **纸感底色**：每个场景都有自己的纸色，但都保留暖灰、米白、灰青等低饱和纸感。
2. **水墨与细线**：山脊、枝条、雨雪、昆虫都用细线、淡墨、透明叠色绘制，避免写实照片感。
3. **印章与版式**：左上角固定「廿四」朱印、节气名竖排、拼音与日期用等宽小字，形成书籍目录般的秩序。
4. **固定的信息层**：右上太阳黄经、右下节气轮盘、底部 5 秒进度线，让 24 个画面共享同一套 HUD。

区分度主要来自三件事：

1. **每个节气一套纸/墨/主色/辅色**，例如立春是暖米色与嫩绿，大暑是深墨绿与焦橙，冬至是近黑蓝与朱红。
2. **每个节气一个视觉母题**：破土、归雁、春雷、荷塘、麦浪、鸣蝉、银杏、霜柿、压竹、灯笼、喜鹊、寒江独钓等。
3. **天气与动势不同**：雨、雪、雾、风、雷、流萤、水波、花瓣、纸鸢，分别承担不同的运动节奏。

### 4.2 版式

- **桌面/横屏**：左侧约 1/3 是竖排节气名、拼音、日期、短句；右侧 2/3 是主画面。文字层与画面层通过纸色渐变遮罩衔接。
- **平板/窄屏**：标题改为横排，信息层压缩，轮盘在 720px 以下隐藏，主画面下移，保证标题与画面不互相遮挡。
- **统一框架**：极细的内边框、四角标记、纸纹和暗角贯穿所有场景。

## 五、技术实现

### 5.1 架构

- `TERMS`：24 个节气数据对象，包含名称、拼音、英文、日期、季节、太阳黄经、短句和纸/墨/主色/辅色。
- `scenes`：24 个绘制函数，每个函数只负责一个节气的画面与运动。
- 公共绘制辅助函数：山脊、日月、云、雨、雪、涟漪、风线、芦苇、柳枝、花、鸟、昆虫、房屋、灯笼、渔船等。
- 单 Canvas + `requestAnimationFrame` 渲染；DPR 上限 2，兼顾清晰度和性能。
- 主题切换通过 CSS 自定义属性（`--paper`、`--ink`、`--accent`、`--accent2`）驱动 UI 颜色。

### 5.2 时间与切换

- 每个场景维护 `sceneStart`，当前进度 `p = (now - sceneStart) / 5000`。
- 进度同时驱动底部细线和轮盘上的小弧段。
- 切换时：
  1. 将当前画布复制到离屏 canvas；
  2. 新场景立即开始绘制；
  3. 在 1 秒内把旧画面按缓动透明度覆盖回去，并画一条淡墨扫线；
  4. 文字在 210ms 后淡出再淡入，避免和新画面硬切。
- 空格键会重置 `sceneStart`，因此手动切换后同样拥有完整 5 秒。

### 5.3 程序化图形

- 山脊：多组正弦叠加生成轮廓，再叠加低透明度渐变。
- 雨雪：基于种子伪随机的粒子，随全局时间循环，无粒子对象分配。
- 花木：贝塞尔曲线组合成花瓣、叶片、柳条、麦穗、竹叶。
- 纸纹：CSS 内联 SVG `feTurbulence` 生成噪点，不请求外部图片。
- 每帧使用确定性随机函数 `hash/rnd`，避免画面闪烁和不可复现。

### 5.4 性能与兼容

- 只在可见区域绘制一个 Canvas；不创建 DOM 粒子。
- 使用 `save/restore` 控制状态，避免全局样式泄漏。
- 需要支持 `color-mix()` 的现代浏览器（Chrome / Edge / Safari / Firefox 近两年的版本）。
- 部分云雾使用 Canvas 2D `filter: blur()`；不支持时只会变成硬边，不影响功能。

## 八、已知限制

1. **字体依赖本机**：没有嵌入 WebFont。缺少中文宋体的机器会回退到系统衬线字体，观感会变化。
2. **日期为常见日期**：不是逐年的天文年历，年份不同可能相差一天。
3. **插画是风格化表达**：花木、昆虫、云山不是植物学/动物学精确复原，优先服务画面气质。
4. **未完整支持减少动态效果**：目前没有针对 `prefers-reduced-motion` 的全量降级；对动态敏感用户，建议后续增加“静态模式”。
5. **没有暂停/播放按钮和 URL 状态**：刷新后从立春开始，不记忆上次节气。
6. **测试环境不随项目交付**：Chromium、Noto CJK 字体和 Playwright 都在 `/tmp`，清理临时目录后需要重新准备。
